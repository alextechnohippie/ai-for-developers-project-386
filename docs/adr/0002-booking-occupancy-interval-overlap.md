# Занятость как список интервалов с проверкой пересечения под единым Mutex

Брони хранятся как интервалы `[начало, конец)` в одной коллекции; создание брони проверяет отсутствие пересечения с любой существующей записью на встречу (любого типа встречи) и целиком защищено одним `kotlinx.coroutines.sync.Mutex` (`withLock`). Так выбрано потому, что шаг стартов равен длительности типа, поэтому брони разных типов дают интервалы разной длины, которые пересекаются, не совпадая по «ключу слота»: занятость нельзя свести к атомарной вставке по одному ключу — нужна диапазонная проверка под замком.

## Рассмотренные альтернативы

- **`ConcurrentHashMap.putIfAbsent` по ключу слота** — атомарен лишь для одного ключа и не покрывает пересечение интервалов разной длины между типами (см. R1).
- **Дискретизация времени в сетку (шаг = НОД длительностей) с отметкой занятых ячеек** — усложняет атомарную «всё-или-ничего» вставку набора ячеек и саму модель; для in-memory хранилища с малым числом броней выгоды нет.

## Следствия

- Критическая секция синхронная (in-memory, без suspend-вызовов) — гонка исключена; проверка линейна по числу броней, что для учебного объёма приемлемо.
- Полуоткрытые интервалы: примыкание разрешено, частичные пересечения отклоняются.
